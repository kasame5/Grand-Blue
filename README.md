# dive-manifest · 潜水店出海船单生成与变更响应系统

> **一张船单，为什么需要版本号？**

因为它不是一张静态名单。它从「预订确认」开始生效，到「离港确认」为止执行；在这段时间里，人会加、会减、会换组，教练会疲劳，气瓶会过期。每改一次，之前那次校验就失效了。

大多数排班工具把这件事当成“编辑一张表”。这个项目把它当成**只有一条生效版本的、被规则门禁约束的、可追溯的快照序列**。

---

## 核心不变量

> **任意时刻，一张船单只有一个“生效版本”。**

- 变更 = 让当前版本失效，生成新版本进入草稿
- 确认 / 锁定 = 把某个版本变成生效且可用
- 离港 = 绑定当时那个生效版本号
- 关闭 = 冻结，不再接受变更

这条不变量决定了后面所有建模：为什么要快照、为什么状态挂在船单上、为什么回滚也是一次版本。

## 规则（8 条，三级）

| ID | 规则 | 级别 | 判定单位 |
|---|---|---|---|
| R-01 | 船只超载 | 阻断 | 单船在船人数 > 核定载客 |
| R-02 | 教练资质不匹配 | 阻断 | 组内成员等级/专长超出教练资质 |
| R-03 | 气瓶不适航 | 阻断 | 组内可用瓶数不足，或存在过期/异常瓶 |
| R-06 | 教练配比不足 | 阻断 | 组内人数 : 教练 > 4:1 |
| R-04 | 教练疲劳 | 警告 | 当日带潜次数 / 间隔 / 累计水下时间 |
| R-08 | 重复分配 | 警告 | 同日多船次，或同船次多组 |
| R-05 | 人员未到场 | 提示 | 集合前 30 分钟未签到 |
| R-07 | 海况未确认 | 提示 | 离港前 2 小时未录入海况 |

**阻断不可豁免**，必须改数据；**警告**可继续但需说明；**提示**进入离港清单。

---

## 状态机

```
草稿 10 → 已确认 20 → 已锁定 30 → 已离港 40 → 已关闭 50
   ↑________|            |
      (变更回草稿) ←──────┘(解锁)
```

确认 / 锁定 / 离港 都要求**阻断为 0**；离港额外要求**离港清单完成**；锁定后必须显式解锁才能改名单。

## 快速开始

```bash
npm install

npm run demo       # 领域层：跑一遍答辩链路（纯文本，带断言）
npm run build      # 构建单文件界面 → dist/index.html
npm run smoke      # 用 jsdom 真的把五屏点一遍
npm run typecheck
```

**界面用法**：直接双击 `dist/index.html`。单文件、全部内联，不联网、不起服务。

## 五屏

| 屏 | 职责 | 在答辩里的作用 |
|---|---|---|
| P1 船单工作台 | KPI、用船与在船人数、冲突概览、变更事件流 | 一眼看出“哪条船满了、卡在哪” |
| P2 船单编制 | 已确认预订池 → 编入分组 → 校验 | 演示“临时新增一名潜水员” |
| P3 冲突与变更影响 | 阻断/警告/提示明细、影响范围、版本 diff | 演示 R-01 / R-02 / R-06 三条阻断 |
| P4 分组与资源调配 | 分组看板、选中人员 → 移入目标组、教练池、气瓶池 | 演示“调换分组解除超载” |
| P5 版本审计与离港 | 版本时间线、与上一版差异、站内通知、离港清单、状态动作 | 演示 v1→v2→v3 与锁定、离港守卫 |

答辩主链：**P2 新增 → P3 看阻断 → P4 调组 → P5 确认/锁定/离港**。任何一步点错，右下角「重置演示」可以回到初始状态。

## 目录

```
src/
├─ domain/                 领域层（不依赖 React，可单独跑）
│  ├─ types.ts             实体与快照；判定输入的唯一形状
│  ├─ codes.ts             区间码 / 状态码
│  ├─ rules/
│  │  ├─ defs.ts           8 条规则的元数据（可配置、可开关）
│  │  └─ checks.ts         8 个判定函数（纯函数）
│  ├─ evaluate.ts          聚合判定、算门禁、稳定排序
│  ├─ stateMachine.ts      状态迁移表 + 守卫
│  ├─ version.ts           版本、快照、diff、回滚
│  └─ mutations.ts         纯函数式变更（增删人、调组）
├─ data/seed.ts            答辩场景种子数据（19 人）
├─ scenarios/answer-chain.ts  答辩链路（无界面，可当验收脚本）
└─ ui/                     五屏界面（React）
   ├─ App.tsx / store.ts   外壳与状态机驱动
   ├─ components.tsx       冲突项、diff、门禁条
   └─ screens/P1—P5.tsx
```

**领域层与界面解耦**：`src/domain` 里没有一行 React，可以单独被 Node 脚本调用（`npm run demo` 就是这么跑的）。

## 构建方式说明

本环境禁止 `spawn` 子进程，所以 vite / esbuild 的原生打包器全部不可用（它们都要起一个子进程）。构建改成纯进程内方案：

1. TypeScript Compiler API 输出 CommonJS
2. browserify（纯 JavaScript）打成单文件
3. 把 JS 与 CSS 一起内联进 `dist/index.html`

代价是构建脚本长了一点，好处是产物就是一个 HTML，答辩现场没有任何环境依赖。

## 设计决策

完整记录见 [`docs/adr/`](docs/adr/)：

| ADR | 决策 | 代价 |
|---|---|---|
| [0001](docs/adr/0001-version-as-full-snapshot.md) | 版本存整单快照，不存差异 | 存储冗余 |
| [0002](docs/adr/0002-status-on-manifest.md) | 状态挂船单，不挂版本 | 历史状态要另记一列 |
| [0003](docs/adr/0003-tanks-bound-to-groups.md) | 气瓶挂分组，不挂个人 | 个人级追溯弱 |
| [0004](docs/adr/0004-no-booking-entity.md) | 不建模预订实体 | 系统内无法退改 |
| [0005](docs/adr/0005-rollback-is-a-version.md) | 回滚也是一次版本 | 版本号会变多 |
| [0006](docs/adr/0006-snapshot-as-eval-input.md) | 判定只吃快照 | 组装快照有一次性成本 |
