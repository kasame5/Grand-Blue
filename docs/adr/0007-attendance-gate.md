# ADR-0007 到场状态决定离港门禁，弃权是一次变更

- 状态：已采纳
- 日期：2026-11-13

## 背景

原来的 R-05“人员未到场”是一条固定为提示的规则：从集合前 30 分钟开始报，一直挂到离港都不变。带来三个问题：

1. **语义漂移**：12:05 的“还没到”和 12:55 的“还没到”是完全不同的事，系统却说同样的话。
2. **拦不住**：提示不参与门禁，人可以不来，船照样开。
3. **有后门**：离港清单里的“人员全部签到”能一键勾选，直接绕过校验。

## 决策

**1. 一条规则、三个时段、三种级别（R-05，标注 `escalating`）。**

| 时段 | 级别 | 含义 |
|---|---|---|
| 集合前 30 分钟 | 提示 | 提醒，人可能还在路上 |
| 过了集合时间 | 警告 | 迟到 N 分钟 |
| 离港前 15 分钟 | 阻断 | 未处置，不能走 |

级别默认仍由 `RuleDef` 决定；“可升级”只是给这一类随时间变化的规则开的一个显式例外（目前仅 R-05）。

**2. 每个人必须有明确归宿：签到，或弃权。**

弃权不是打勾，是一次**变更**：从分组移出、收回一支气瓶、解除当日分配、生成新版本。因为人数变了，配比、气瓶数量、分组结构都会跟着变。

**3. 离港清单中的两项不能手工勾选。**

- 海况确认 → 看 `trip.seaCondition`
- 人员到场 → 看是否还有未处置的人

清单由 `deriveChecklist()` 从状态推导，手工只能勾“气瓶装船 / 救生设备 / 离港申报”。

## 理由

1. “未签到”和“未处置”是两件事：前者是没来，后者是还挂在名单上。船单必须反映真实在船的人，否则离港绑定的版本是假的。
2. 若只做提示，规则等于没有——这是“阻断不可豁免”原则的延伸。
3. 清单可手工勾选，等于给门禁留后门；能绕过的门禁不算门禁。

## 代价

- 锁定之后若要弃权，必须先解锁（因为弃权是变更，会生成新版本）。
- 演示流程变长：确认 → 锁定 → 离港被拒 → 弃权 → 重新确认 → 锁定 → 离港。
- 需要新增 `Diver.attendance` 字段，并对历史快照做兼容。

## 备选方案

- **把 R-05 拆成三条规则**（未到场提醒 / 迟到 / 未处置）：规则数从 8 变 10，能保住“级别是规则属性”的纯度，但文档、界面、答辩口径全要跟着改。选择升级机制，是为了让规则表仍然是 8 条。
- **允许店长强制勾选清单**：实现最简单，但等于取消门禁。
