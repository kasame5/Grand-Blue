# ADR-0008 资质拆成三件事：潜水员等级、潜点要求、带队资质

- 状态：已采纳
- 日期：2026-11-13

## 背景

原来的 R-02 是这样判的：

```ts
教练资质：['OW']
潜水员等级：'AOW'
规则：AOW 学员 → 需要 AOW 资质的教练
```

它把三件不同的事压成了一个映射，导致两个问题：

1. **`['OW']` 有歧义**：是「OW 潜水员」还是「OWSI（开放水域教练）」？界面显示 `OW`，读起来像前者，本意是后者。
2. **把教学关系和带队关系混为一谈**。持证潜水员参加 fun dive 时，并不存在「谁教谁」；真正约束的是潜点深度、潜水员等级、以及带队者能带多深。

最直接的证据：李明是 AOW，被编进「只有 OW」的王强那组，系统报「李明需要 AOW 资质」——**这句话在业务上不成立**，因为根本没有教学关系。

## 决策

拆成三个独立概念，R-02 逐项判定：

| 概念 | 字段 | 决定 |
|---|---|---|
| 潜水员等级 | `Diver.level` + `Diver.specialties` | 这个人能下多深（OW 18m / AOW 30m / 深潜专长 40m） |
| 潜点要求 | `Trip.depth` / `requiredLevel` / `requiredSpecialties` | 这次潜水本身要求什么 |
| 带队资质 | `Instructor.rating` / `maxSupervisionDepth` / `specialties` | 这个人能带队到多深、能带什么专长 |

判定三类（全部阻断）：

1. 潜水员最大深度 < 潜点深度
2. 潜水员缺少潜点要求的专长
3. 带队者带队上限 < 潜点深度，或缺少所需专长

深度数值采用通行标准：OW 18m / AOW 30m / 深潜专长 40m；教练等级区分 潜水长 / 开放水域教练 / 进阶教练 / 专长教练。

## 理由

1. 三者是**独立约束**，任何一个不满足都会出事，不能用一个映射代替。
2. 修正后，主链路「AOW 潜水员进 OWSI 的组」不再报错——**因为它本来就不该报错**。旧的第三条阻断是建模造成的假象。
3. 新模型能判出旧模型完全看不见的情况：潜点 32m 时，OW 潜水员和带队上限 30m 的教练都会被挡。

## 代价

- 主链路的阻断从「R-01 / R-02 / R-06」变成「R-01 / R-03 / R-06」：新增人员时没配气瓶，由 R-03 顶上。R-02 移到补充演示。
- 课程文档的规则表、答辩场景表、ER 都要跟着改。
- 需要给 Trip 增加 `depth` / `requiredLevel` / `requiredSpecialties`，给 Instructor 换掉 `qualifications`。

## 备选方案

- **保留旧映射，只把 `['OW']` 改名为 `OWSI`**：能消除歧义，但判不出深度与专长，本质问题还在。
- **按课程类型分别建模（教学单 / fun dive 单）**：更贴近真实，但对课程作业是过度设计。
