# ADR-0002 状态挂在船单上，不挂在版本上

- 状态：已采纳
- 日期：2026-11-12

## 背景

“已锁定”“已离港”这些状态，既可以看作整张船单的状态，也可以看作某一个版本的状态。两种建模都能跑，但会导出不同的界面和不同的提问方式。

## 决策

状态是**船单**的属性。版本只记录“生成时船单处于什么状态”（`statusAtCreation`），本身不持有生命周期。

## 理由

1. 业务上人说的是“这张单现在什么状态”，没人说“v2 现在是锁定态”。
2. 任意时刻只有一个“当前版本”，状态跟着它走是自然的。
3. 状态机只需要维护一份，不会出现“v1 已锁定、v2 草稿，那这张单算什么状态”的歧义。

## 代价

历史版本的状态要单独记一列；回看某个旧版本时，要读 `statusAtCreation` 而不是实时状态。

## 备选方案

- **状态挂版本**：能精确表达“v1 锁定、v2 草稿并存”，但界面要同时呈现两个状态，答辩时也不好讲清。

## 影响

- `Snapshot.manifest.status` 是唯一状态来源。
- 状态迁移表（`stateMachine.ts`）显式写成数据，不散落在 if 里。
