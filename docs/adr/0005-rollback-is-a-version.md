# ADR-0005 回滚也是一次版本

- 状态：已采纳
- 日期：2026-11-12

## 背景

变更发起后，店长可能决定放弃，回到变更前的状态。最直觉的做法是“删掉新版本、把状态退回去”。

## 决策

不删除任何版本。回滚实现为：**以目标版本的内容生成一个新版本**，原因记为“放弃变更，回滚至 vN”。

## 理由

1. 和 ADR-0001 一致：版本只增不改，审计链才成立。
2. 一旦开了“可以删除版本”的口子，“哪个版本真的生效过”就说不清了。
3. 实现上不需要特殊路径：回滚只是“拿旧快照再存一次”。

## 代价

版本号会增加（v1 → v2 弃用 → v3 回滚），看起来“多了一版”。需要在界面上用状态标签区分“弃用”和“生效”。

## 备选方案

- **物理删除 v2**：界面干净，但审计链断裂，且掩盖了“确实有人动过手”这个事实。

## 影响

- `makeRollback()` 生成 `kind: 'rollback'` 的新版本。
- 版本列表永远只增，界面用生命周期标签（生效 / 失效 / 弃用 / 冻结）表达语义。
