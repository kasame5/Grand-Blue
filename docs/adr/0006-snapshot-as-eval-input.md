# ADR-0006 判定只吃快照，规则内部永不查询

- 状态：已采纳
- 日期：2026-11-12

## 背景

规则要判断超载、资质、气瓶、疲劳、签到。最省事的写法是让每条规则自己去查数据，缺什么查什么。

## 决策

所有规则接收同一份**只读快照** `Snapshot`，判定过程中不再取任何外部数据；“现在几点”通过 `EvalContext.now` 显式传入。

## 理由

1. **可测**：规则是纯函数，给定快照就有确定结果，不需要起数据库。
2. **可回放**：同一份快照判十次结果一致，历史版本可以被重新解释。
3. **可解释**：判定用到的数据全部在快照里，答辩时可以直接展示“它看到了什么”。
4. **可演示时间**：`now` 是参数，所以能拨到“集合前 30 分钟”看提示出现，而不是等真实时间。

## 代价

组装快照需要一次性的读取成本；快照可能比“按需查询”多取一些当前用不到的数据。

## 备选方案

- **规则内查询**：写起来快，但规则不可单测、不可回放，且会随时间演变成隐式依赖网。

## 影响

- `RuleCheck = (snap, params, ctx) => Finding[]`。
- 规则内部禁止出现 `Date.now()`、数据库调用、随机数。
- 需要“当日其他船次”的 R-08，通过在快照里附带 `dayAssignments` 解决，而不是让规则自己去查。
