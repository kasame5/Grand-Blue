# ADR-0001 版本存整单快照，不存差异

- 状态：已采纳
- 日期：2026-11-12

## 背景

船单在“确认之后、离港之前”会反复变更。每次实质变更都要留下一个可追溯的版本，问题是用什么方式存这一版。

## 决策

每个版本保存**完整的船单快照**（人员、分组、教练、气瓶、船只、船次、规则命中结果），而不是只存相对上一版的差异。

## 理由

1. **可回滚**：拿到任一版本号就能还原当时的执行状态，不需要按顺序重放差异。
2. **可解释**：离港时要能证明“当时就是这些人、这些瓶”，快照本身就是证据。
3. **可 diff**：差异在展示时实时算，不会出现“存的 diff 和实际内容对不上”。
4. **实现简单**：没有重建逻辑，也就没有重建 bug。

## 代价

存储冗余。同一批人会在多个版本里重复出现。课程规模下可以忽略；真实门店需要定期归档冷版本。

## 备选方案

- **只存差异**：省空间，但回滚要重放，历史一致性难保证。
- **快照 + 差异双写**：两者可能不同步，需要额外一致性校验。

## 影响

- `ManifestVersion.snapshot` 持有完整快照。
- diff 由 `diffSnapshots(before, after)` 实时计算，不落库。
